## 目的と体制

タオルソムリエのゲームをもとに、小学4年生〜中学生向けのスマホのブラウザゲームのテスト版（プロトタイプ）を、Claude Code で作る。本格版はプロが作る。このテスト版は、最終案まで作り続ける土台。

- 仮タイトル: 消えたタオルと白い記憶 〜消えたレシピを探す旅〜〔10/2〕
- ターゲット: 小学4年生から中学生が中心。大人も楽しめる入門ゲーム〔10/2〕
- 作る期間と時間: 1か月、1日60分ほど（遊ぶ時間の目安とは別）〔10/2・10/25-22〕
- 元資料: 9/7 関係者共有まとめ、9/14 確認事項、タオルの学校_入門編_v53_カード一覧.xlsx、タオルの学校_入門編_v53.html。食い違うところは9/14を優先〔10/2〕
- 役割分担: 本人の試作はバトルとクイズ。世界観、キャラ、本格版の音楽、背景、絵は制作担当者（デザインチーム）が作る〔10/2〕
- 入門編（v53）のコードは使わず、新しく作る。v53から使うのはカードとクイズの知識データだけ。学校の呼び方（1年生・卒業など）は使わず、世界名（原材料の世界・製造工程の世界・タオル進化の世界）にする〔10/2〕
- 直しやすさ（どこを触れば何が変わるか）をゲーム性と同じ重さで扱う。仮で済ませていたところは、順に本物の作りに置き換える〔10/21-1〕
- 直す場所は3つ: ことばのデータ（data/words.js）、ステージの数値（data/stages.js）、画面の言葉（data/texts.js）〔10/21-1〕
- 進め方: 世界1の最初のステージを通して遊べる形にしてから広げる。公開は GitHub Pages、スマホはURLで開いて試す。ゲーム（バトル）が先、シナリオはあと。細かい調整は触って決める〔10/2〕

### 運用

- チャットは「決める場所」、Claude Code は「作る場所」。「決定:」で始まる指示は、この文書の該当する項目を書き換え（出どころの番号を更新）、docs/変更の記録.md のいちばん下に日付つきで足す〔10/2・10/25-22・10/25-25〕
- Claude Code は、作業の終わりに進捗メモ（今日やったこと、次にやること、判断待ち）を更新する。言葉の置き換えのときは、今を説明する節（今の状態の先頭、次にやること、判断待ち）だけ直し、過去の記録（今日やったこと、版の一覧、日付つきの記録）はそのときの言葉のまま残す〔10/2・10/31-4〕
- 大きく変える前は、先に計画を見せてから作る。作業中に判断が必要になったら、Claude Code で決めず、進捗メモの判断待ちに書いてチャットに持ち帰る〔10/2〕
- 1日60分の型: 最初の5分で進捗メモを読む、中の45分で作って確かめる、最後の10分で動く状態にして保存する〔10/2〕

## データ

- 120のことば（世界ごとに40、ステージごとに10）は、data/words.js に1か所でまとめる。今はv53の120語〔10/2〕
- ことばごとの欄: id、ステージ、ことば、読み、問題、選択肢（2つか3つ）、正解の番号、一言メモ、役割（ザコ／中ボス／大ボス）、硬さ、正解・不正解のときのふわりのセリフ、出る順番、出方、出る位置、文字ごとの読み（中ボス・大ボス）、お題の問い〔10/2・10/3・10/5・作り〕
- 問題・選択肢・正解・一言メモ・お題の問い・ふわりのセリフは、words.js の欄だけに持つ。game.js や quiz.js に問題の文章を書かない。words.js の1行を直せば、お題もクイズもカードも同時に変わる〔10/3-13〕
- お題の問い（odaiQuestion）は、答えがそのことば自身になる形（「〜は？」）。空なら問題（question）を使う。ふつうのクイズの問題文は変えない〔10/5・10/3-13〕
- 並べかえの問題（製造工程の世界に多い）は、順序そのものを選択肢にして3択にする（例: ABC／ACB／BAC）〔10/2〕
- 大ボスはv53の各ステージの「boss」から。中ボスは仮置きで、最後に本人が決める。入れかえは役割の欄を書きかえるだけ〔10/2〕
- ステージ1は、大ボス「天然の撚り」、中ボス「コットンボール」「繊維長」〔10/3・10/25-17〕
- 出方の型: ふつう、端にかくれる、横切る、虫のうしろ（雑魚のうしろ）、木のかげ、地上（世界2から）〔10/3・10/8・作り〕
- ステージ1は、出方を words.js の欄で決める（ルーメン＝端にかくれる、リント・植物繊維＝横切る、リンター＝虫のうしろ）。ステージ2からは、意地の悪いことばの数（難易度の線）から自動で決める（毎回同じ並びになる）〔10/3・作り〕
- words.js の先頭に、欄の意味と直し方の説明がある。120語は docs/words.csv にも書き出し、表計算で直せる。行き来は tools/words_csv.js（export／import）〔10/3-13〕
- ことばに関係しないふわりの決まり文句（クイズの「そうだ！思い出した！」など）は js/quiz.js の FUWARI_SAY〔10/3-14〕
- stages.js の欄: ステージ名、トピック、宝石の名前（recipe 欄）、宝石の色、遊べるか、難易度、出方の決め方、発見の動きの型、木、天気、時間帯の色と背景の絵と虫、ステージごとの数値の上書き、チュートリアルの印〔作り〕
- texts.js: 画面の言葉をすべてここに置く。世界ごとにちがう言葉（種の名前など）は世界ごとに持つ〔10/21-1〕

## ふりがなの決まり（検討版）〔11/7-18〕

- どの語につけるか: 小学4年生までに習う漢字（学年別漢字配当表 2020年 の1〜4年、642字。tools/kanji_g1-4.txt）だけの語にはつけない。5年生以上の漢字か、表にない漢字をふくむ語につける
- 語の単位でつける。送りがなにはつけない（「晒し」なら「晒」の上に「さら」）。漢字のかたまりが2つある語は、かたまりごと。漢字が続く名詞はまとめて1語（「紡績工場」の上に「ぼうせきこうじょう」）
- 読み: 120語の kana を優先（文の中でその語がちょうど1語として出るとき）。それ以外は辞書（kuromoji・IPA辞書）。辞書がまちがえた・読めなかった語は tools/ruby_build.mjs の MANUAL に手で入れる（吸水速乾・混打綿・混綿・梳綿・綿あめ・後染め・強撚り・後晒し・日本独特）
- kanaParts（ボスの1文字ずつの読み）は、救出の旅で文字をこわしたときの読みのまま。文のルビには使っていない（文の中のボスの語は kana で足りた）
- 作り方: tools/ruby_build.mjs が words.js・stages.js・texts.js を読んで data/ruby.js（文ごとの読みの表と、語の表）と docs/ふりがな一覧_1107.md を作る。words.js や texts.js の文を直したら、作り直す（手順は ruby_build.mjs の頭）

## 版の管理

- 公開は GitHub Pages。親のURL（https://nttakahiro-ui.github.io/kieta-towel/ ）は常に最新版〔10/7-1〕
- 作業した日ごとに、その日の最後の版を versions/YYYYMMDD/ に丸ごとコピーして公開し、タグ v日付 をつける〔10/7-1・10/21-1〕
- 公開済みのタグは動かさない。同じ日に何回も公開したときは、タグに b、c…と足す（今は v20261025t まで）〔10/25-4〕
- 進捗メモの先頭に版の一覧（日付、URL、タグ、その版の要点）を置き、版を増やすたびに更新する〔10/7-1〕
- 案内を見た記録は、版（versions/ のフォルダ）ごとに分けて保存する。別の版を開いたときは案内が出る〔10/7-1〕
- 検討版は versions/kento/（URL https://nttakahiro-ui.github.io/kieta-towel/versions/kento/ で固定。改良が続いてもURLは変えない）。タイトル画面の小さな表記「検討版 11/7」は、公開のたびに日付だけ手で直す。古いURL versions/20261106/ は新しいURLへ自動で飛ぶ1ページだけ。遊んだ記録の保存名は kietaTowel.save.20261106 のまま。案内を見た記録も、前の場所（versions/20261106/）の名前のまま使う〔11/7-10〕
- 公開のたびに index.html の ?v= の番号を上げる（スマホの古い読みこみを避ける）〔作り〕
